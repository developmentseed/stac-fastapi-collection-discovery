Is the federated keyword search part of the project in its own right, or only the fallback for clients that do not send `query`? (Re-asks Q4, whose block was removed while the gap stayed open.)
- Q7 How do the researchers reach the natural-language search?: "Who it is for" says the audience searches catalog portals by hand today. The natural-language search is reached only through `query`, which no plain STAC client sends. In this repo only streamlit_app.py sends it (line 41); the STAC Browser that `docker compose` brings up (README lines 36-42) gets keyword search. The demo is not the product. Outside the demo, how does a researcher reach the product: only through the demo while the experiment runs, or does the direction include a client they would use?

- Q8 What about catalogs that ignore free-text search?: src/stac_fastapi/collection_discovery/search.py (lines 3-9) notes that many catalogs ignore `q` entirely. For those, every term returns the same unfiltered first page of collections, and the re-ranker picks only from that page. With no index (Non-goals) and no change upstream (this line), such a catalog cannot really be searched. Is it in scope and judged on its first page, or left out of the catalogs this project searches?
